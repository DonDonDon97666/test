# 场景1：敏捷迭代项目计划

## 1. 计划逻辑

采用“1周 Sprint + 持续集成 + 每个 Sprint 可演示”的方式，不按前后端完全串行开发。

拆分原则：
- Sprint 0：技术底座与需求澄清
- Sprint 1：草稿与基础信息
- Sprint 2：AI理解与附件
- Sprint 3：主数据/历史确认
- Sprint 4：提交控制与完整闭环
- Sprint 5：质量强化与上线准备

## 2. Sprint 总览

| Sprint | 目标 | 主要交付 |
|---|---|---|
| S0 | 建立研发基线 | PRD确认、架构、数据模型、API契约、工程脚手架 |
| S1 | 跑通草稿 | Vue工作台、草稿、会话、附件上传、详情 |
| S2 | 跑通AI整理 | AI编排、结构化字段、追问、附件解析 |
| S3 | 跑通事实确认 | 物料、供应商、历史采购候选与用户确认 |
| S4 | 跑通正式提交 | 后端确定性校验、相似提醒、最终确认、幂等提交 |
| S5 | 质量与发布 | 回归、异常、权限、性能/稳定性检查、Demo/README |

## 3. Sprint 任务

### S0
- PM：项目范围、风险、节奏、Definition of Done。
- 产品：需求基线、流程与验收标准确认。
- 后端：微服务边界、DB模型、API契约、权限模型。
- 前端：Vue工程脚手架、状态管理、页面骨架。
- 测试：测试策略、测试数据、核心用例框架。

### S1
- 前端：需求列表、工作台、结构化信息区、附件区。
- 后端：需求服务、草稿持久化、附件元数据。
- 测试：草稿、刷新恢复、权限隔离、上传异常。
- 产品：验收草稿闭环。

### S2
- 后端：AI编排服务、结构化输出Schema、附件解析任务。
- 前端：AI对话、待确认/候选/来源展示。
- 测试：AI成功/失败/超时、会话切换、附件解析。
- 产品：确认AI边界和用户交互。

### S3
- 后端：物料/供应商/历史查询接口及确认记录。
- 前端：候选选择、历史引用、确认状态。
- 测试：停用对象、查询失败、多候选、历史引用。
- 产品：业务事实确认验收。

### S4
- 后端：提交校验、相似申请提醒、幂等提交、审计。
- 前端：提交前校验、最终确认、详情页。
- 测试：重复提交、并发、状态冲突、主数据变更。
- PM：发布风险评估。

### S5
- 全员：回归、缺陷收敛、Demo。
- QA：完整回归与发布报告。
- 后端：日志、监控、异常恢复。
- 前端：兼容性和交互缺陷。
- 产品：最终UAT。
- PM：上线评审和复盘。

## 4. 每个 Sprint 的完成定义（DoD）

- 代码合并并通过 Code Review。
- 单元测试/必要自动化测试通过。
- QA核心用例通过。
- 严重/阻塞缺陷为0。
- 需求验收标准已验证。
- API文档同步更新。
- 可部署版本可构建。
- Demo路径可执行。
