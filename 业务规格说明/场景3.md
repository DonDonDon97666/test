# 实操考核题册## 统一考核说明### 一、统一交付内容1. 完整项目：包含完成指定场景所需的前端、后端及相关服务实现，以及git地址。2. README：说明项目如何启动、环境与配置、数据初始化、模型配置、主要业务流程、已实现范围、重要技术取舍、简化或未完成内容，以及继续开发时的优先补齐方向。3. 接口文档：说明主要前后端接口及业务服务之间的契约，文档形式不限。4. 系统设计图：至少包含一张系统整体架构图，以及一张能够说明核心业务状态或关键交互时序的设计图。5. 现场 Demo：应试者需要现场演示完整业务闭环，并能够解释关键设计、数据一致性、权限与 AI/确定性规则边界。# 场景 3  商业物业租赁续约谈判 Agent## 业务背景某商业园区运营公司需要持续处理办公室租赁续约。资产经理会参考当前租金、市场指导价、面积、剩余租期、客户等级、免租期、押金以及最低收益要求，与租户进行多轮谈判。公司希望通过 AI Agent 辅助生成可解释的续约策略、谈判建议和成交概率判断，但所有金额、折扣、收益底线和审批条件都必须由确定性业务规则控制，不能直接采用模型生成的数字。## 业务角色1. 资产经理：发起续约会话、查看报价方案、录入租户反馈、切换报价策略、确认成交。2. 招商主管：查看会话摘要、风险与僵局事件，必要时参与审批或业务复核。3. 租户：不直接登录系统，租户反馈由资产经理录入，或由系统提供的对话方式模拟。## 业务目标|目标闭环<br />初始化续约会话 → 基于合同、市场和规则生成多套可执行报价方案 → Agent 解释策略 → 资产经理录入租户反馈 → 进行多轮建议与预测 → 必要时切换报价版本 → 达成一致后由用户确认 → 写入续约结果或进入审批；无法收敛时形成僵局事件。||---|## 确定性报价与规则控制系统需要基于合同事实、市场指导价和规则配置形成至少三种不同策略方向的续约方案，例如保守、目标和激进方案。方案应能够解释年租金、折扣、免租期、押金变化、预期收益、是否触碰底线及相应风险依据。所有金额、折扣、利润、收益率、底线和审批阈值必须由确定性程序计算和校验。模型可以解释方案、提出谈判策略或总结反馈，但不能自行决定真实报价数字。## Agent 多轮谈判续约会话应支持多轮租户反馈。Agent 使用真实模型理解反馈、给出下一步谈判建议、说明风险并形成成交概率或趋势判断。模型输出需要经过结构化约束和业务校验，不能因为模型返回格式异常就直接把原始文本当作可执行业务结果。用户可以在谈判过程中切换报价版本。历史轮次必须能够解释当时使用的是哪一版合同输入、市场数据、规则版本、报价版本和模型版本，不能因为后续规则变化而静默改写历史结论。## 成交确认、审批与僵局最终成交必须由资产经理明确确认。如果最终条件超出公司设定的审批阈值，应进入待审批状态，而不是直接生效。重复确认成交不能重复创建续约记录或重复触发审批。系统应能够根据连续多轮偏离底线、租户明确拒绝、超过合理谈判轮次等情况形成僵局事件。僵局用于提醒和复盘，不应由系统自动对外发送承诺或修改合同。## 需要正确处理的异常与边界1. 市场指导价缺失时，系统不能伪造市场事实，应明确提示数据缺口，并按照可用规则决定后续可执行范围。2. 真实模型返回非法字段、非结构化文本或无法解析内容时，系统仍应保留确定性报价结果和安全的下一步，而不是直接报错或执行原始文本。3. 用户切换报价版本后查看旧轮次时，历史内容应与原版本保持一致。4. 重复成交确认时不能重复创建续约记录或重复进入审批。5. 会话进行中规则被更新时，当前会话和历史轮次需要能够说明各自使用的规则版本；新规则不得静默重写旧结果。## 完成后的业务结果最终应能够演示至少一段具有多轮反馈的续约谈判，从规则生成报价、Agent 给出策略、租户反馈、报价版本切换、趋势判断，到最终成交确认、进入审批或形成僵局。系统需要清楚体现“模型建议”和“确定性报价/审批规则”之间的边界。
